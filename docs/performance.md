### 수치가 의미하는 범위

**송신량.** k6 API에서 5,000 VU가 확인된 유지 구간 내부의 서버 1초 샘플 400개(`[126:526]`)를 평균냈습니다. 명목상 7분 전체 평균은 아닙니다. [ThroughputRecorder](../game-service/src/main/java/com/pomingmatgo/gameservice/global/metrics/ThroughputRecorder.java)는 `LongAdder`로 송신 Publisher 완료를 집계하며, 이는 클라이언트 ACK가 아닙니다. 실행 중 조회는 근사 집계입니다.

**RTT.** k6의 `Date.now()`로 액션 전송부터 첫 정상 메시지까지 측정합니다. 요청 ID로 응답을 대응시키지 않아 다른 알림이 먼저 오면 그 시간도 표본에 포함됩니다. 측정 중 wall clock과 monotonic 경과가 약 64.84초 달랐으므로 RTT와 k6 전체 rate는 시계 영향 가능성이 있는 관측값입니다. 후속 짧은 실행에서는 재발하지 않았지만 원래 표본을 보정한 것은 아닙니다.

**종료 집계.** 증가·유지 구간에는 오류 로그가 없었습니다. 감소·종료 구간에서는 5,000개의 방 실패 로그와 `5,000 interrupted iterations`가 남았으나 방 실패 카운터는 0이었습니다. 후속 1방 실험에서 예정된 VU 취소 후 메트릭 수집이 끝나도 콜백 로그가 남는 경계를 재현했습니다. 실행 중 실제 서버 단절 대조군은 실패 1건을 집계하고 코드 108로 전체 중단했습니다. 이를 모든 종료 로그의 개별 원인 증명이나 전체 실행의 ‘오류 로그 0’으로 해석하지 않습니다. 반복 실행 단위인 iteration과 GAME_OVER로 센 완주 판수도 서로 다릅니다.

**자원 회수.** k6 종료 직후·15초·60초의 서버 포트 ESTABLISHED 연결은 0이었고 송신 누계는 멈췄습니다. 60초 뒤 heap used 약 858MiB, RSS 약 2,212MiB가 관측됐습니다. 강제 GC·내부 객체 생존 분석은 수행하지 않아 메모리 누수 유무나 모든 방·타이머·구독의 회수까지 판정하지 않습니다. WSL 가용 메모리 최저는 약 4,038MiB, 스왑 사용은 없었습니다.

원시 로그·summary·송신 샘플·명령·소스 해시는 로컬 `loadtest/results-1d/webflux-full-run3/`, 후속 종료 실험은 `webflux-termination-audit/`에 보관되어 있습니다. 두 디렉터리는 Git 제외 대상이므로 공개 저장소에는 포함되지 않습니다. 이 문서는 그 결과 요약이며 원시 자료가 공개된 벤치마크는 아닙니다.

## 재현과 판정

실행 명령은 [README의 검증 절](../README.md#검증)에 있습니다. 일반 스크립트는 양쪽 자신의 CONNECT·START 수신을 기다리고 준비·선택을 순서대로 보냅니다. 양쪽 GAME_OVER 후 재준비하며, HTTP 생성·입장 또는 방 실행 실패 시 양쪽 소켓·예약을 정리하고 전체 실행을 중단합니다. 자동 재시도는 하지 않습니다.

| 현재 threshold | 통과 조건 |
| --- | --- |
| checks | 성공률 > 99% |
| 게임 액션 RTT | P95 < 1,000ms |
| 서버 오류 / 무응답 timeout | 각각 100건 미만 |
| 방 실패 | 0건 |
| AFK 스크립트 checks | 성공률 100% — 양쪽 GAME_OVER와 오류 없음 |

서버 송신량은 `GET /internal/metrics/throughput`의 `perSecond`에서 유지 구간을 분리합니다. 같은 조건으로 비교하려면 커밋·클라이언트 지연·프로파일·로그·JVM·계측 설정과 실제 VU 구간을 함께 기록해야 합니다. 시스템 시계와 단조 시간도 함께 관측합니다. k6와 서버가 자원을 공유하므로 이 결과를 운영 처리량 보장으로 해석하지 않습니다.

종료 판정에는 카운터뿐 아니라 최초 오류 시점·전체 로그·interrupted 수·종료 코드를 함께 사용합니다. 취소 시각에 가깝다는 이유로 실제 단절을 무시하거나 threshold를 완화하지 않습니다.

## 회귀 검증의 범위

- **서버:** 2026-10-01 `6d547de`에서 전체 60개 클래스 488개 통과, 실패·오류·skip 0. 실제 loopback WS/TCP 7개 클래스 24개가 포함됩니다.
- **클라이언트:** 준비 흐름 수정 후 같은 날 Node 제어 테스트 25개 통과. 실제 k6 최대 10방·63판 통과, HTTP 충돌 1회 뒤 전체 abort 확인 후 본 부하로 진행했습니다.
- **해석:** 게임 규칙·내부 취소/장애 주입·제한된 실제 소켓 검증을 구분합니다. 실제 소켓 테스트 통과가 장시간 느린 수신의 메모리 상한, Redis 런타임, 외부 프런트엔드 적용을 검증한 것은 아닙니다.
